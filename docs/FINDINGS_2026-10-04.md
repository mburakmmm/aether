# 2026-10-04 bulguları: `--release` derlenmiyor, echo ping’den uzak

**2026-10-06 güncelleme.** Saf Nox ölçümü (noxc 1.138, `wrk -t4 -c40`) ping ile JSON-echo arasını %11’e indirdi. Aether’deki daha büyük farkın ana parçası JSON değilmiş: `dispatch` her istekte `is_stopping()`’i iki kez çağırıyor, her çağrı `getenv` + `access()` yapıyordu. Profilde dispatch süresinin yaklaşık %55’i. `is_stopping`’i `False` yapan geçici kopyada ping 137k → ~210k, echo 105k → ~150k.

Aether tarafı bu dosyadan sonra şöyle:

- `is_stopping` worker başına `AETHER_STOP_POLL_MS` (varsayılan 200) önbellek. `begin_shutdown` / `clear_shutdown` çağıran worker’da anında. Diğer worker’lar dosyayı pencere bitince görür.
- `dispatch_from_parts` artık `peer_addr` alır. Bench handle `""` geçirir (`req.peer_addr` okunmaz, retain yok). `client_ip()` peer’ı kullanır; güvenilen `X-Forwarded-For` varsa o kazanır.

Kalan echo farkı (düzeltmeden sonra ~%29, saf JSON %11) Nox cycle detector (`JsonValue` release → `nox_cycle_possible_root`) ve Aether DTO borusu. Cycle detector Nox tarafında ele alınıyor; bu repo onu değiştirmez.

Aşağıdaki 4 Ekim metni, o günkü LLVM reddi ve o günkü echo hipotezinin kaydıdır. Echo’nun “asıl sebep JSON” cümlesi 6 Ekim ölçümüyle değişti.

İki ayrı iş. Biri Nox derleyicisinde, biri Aether/Nox JSON yolunda. Aether 0.6.6 kaynakları `--release`’i bozmuyor. Ölçüm: `wrk -t4 -c40 -d8s`, darwin arm64, 4 Ekim 2026. Kurulu derleyici **noxc 1.126.0**. Kaynak ağaç **nox-lang 1.129.0** aynı LLVM reddini veriyor.

Sayıların tablosu: [BENCHMARKS.md](BENCHMARKS.md). Eski decode/mmap notları: [PERF_GAPS.md](PERF_GAPS.md). O dosyadaki “çift decode” bölümü 0.6.3 öncesidir; güncel echo tek `nox.json.decode` yapar.

## 1. `noxc build --release` neden düşüyor

### Belirti

QBE geçer (`noxc check`, `noxc build`, `noxc run`). `--release` hem `benchmarks/aether/main.nox` hem `examples/hello_api/main.nox` için şu mesajla çıkar:

```text
codegen: bu program şu an desteklenmeyen bir yapı içeriyor (ör. iç içe fonksiyon/sınıf tanımı, desteklenmeyen bir tip ifadesi ya da bir for döngüsünde range()/list[T] dışında bir iterable)
```

Mesaj yanıltıcı. Kırılan yapı iç içe fonksiyon veya `for` değil. `compiler/main.zig` içindeki `error.Unsupported` kolu her codegen reddini bu cümleye çeviriyor ve düğüm konumu basmıyor.

### Bu değil

- Aether’in 0.6.6 diff’i değil. Aynı red, kilit SHA’sındaki pakette de var: `~/.nox/pkg/mod/github.com/mburakmmm/aether/ddd837a0cefab01dde2f0468aa44d9bb30ebf870` (`nox.lock` `resolved`, v0.6.5 kodu).
- `serve` / `HttpRequest` / worker boot değil. Çıplak `nox.http.serve` `--release` ile derleniyor.
- 1.104.0’taki `--release` bench’inin regresyonu bir Aether hot-path değişikliği değil. O ölçüm, stdlib’de `@capability.requires` yokken alındı.

### Kök neden

LLVM backend’i dekoratör metadata tablosunu hiç taşımadı. Dekoratörlü bir fonksiyon derleme birimine girince `--release` bilinçli olarak reddediliyor:

```1829:1832:compiler/codegen_qbe/codegen.zig
    if (gen.backend == .qbe) {
        try gen.genDecoratorMetadata(decorated_functions);
    } else if (decorated_functions.len > 0) {
        return error.Unsupported;
    }
```

Bu dosya **nox-lang** deposunda. QBE kolu `decorators.zig` `genDecoratorMetadata` ile `$__nox_decorators` tablosunu ham QBE `data` metni olarak yazar (`qbeRaw` / `qbeRawAll`). LLVM’de bu iki fonksiyon unconditionally `error.Unsupported` döner (`compiler/codegen_qbe/llvm_emit.zig`, `qbeRaw` / `qbeRawAll`). Guard olmasa bile tablo üretilemez. Guard, dekoratör varsa üretmeden reddeder.

`@capability.requires` bir checker kapısıdır; çalışma zamanı tablosuna ihtiyaç duymaz:

- `registerCapabilityDecorator` → `capability_functions`
- çağrı anında `checkCapabilityCall` / `checkMethodCapabilityCall`
- profil yetmezse `CapabilityNotGranted`

Aynı dekoratör buna ek olarak `decorated_functions` listesine de eklenir (`checker.zig`, `registerDecorators` sonundaki `append`). LLVM kolu bu listeyi “gerçek dekoratör” sayar. Liste boş değilse `--release` biter.

### Hangi import yetiyor

Aether’in kendi kaynaklarında dekoratör yok. Red, import edilen stdlib’den geliyor. Nox import edilen modülün gövdesini, fonksiyon çağrılmasa da codegen’e sokar.

| `import` | noxc 1.126 `--release` | Neden |
|---|---|---|
| `nox.time` | düşer | `now_ms`, `sleep_ms`, `now`, `instant_now`, `Instant.elapsed_ms`, `Instant.elapsed` üzerinde `@capability.requires("clock")` |
| `nox.crypto` | düşer | `secure_random_hex` üzerinde `@capability.requires("entropy")` |
| `nox.uuid` | düşer | `nox.crypto` import eder |
| `nox.log` | düşer | `nox.time` import eder |
| `nox.http`, `nox.json`, `nox.validate`, `nox.strings` | geçer | bu dekoratör yok |

Aether grafiği şunları çeker:

- `application.nox` → `nox.time`, `nox.log`, `nox.uuid`
- `lifecycle.nox` → `nox.time`
- `dto.nox` → `nox.uuid` → `nox.crypto`
- `aether.jwt` → `nox.crypto`

`import nox.time` tek başına yeter. İstek kimliği ve access log kapalı olsa da `now_ms` derleme birimindedir.

### Yeniden üretim

```sh

printf 'import nox.http\nprint(1)\n' > /tmp/ok.nox
noxc build --release -o /tmp/ok /tmp/ok.nox

# düşer — Aether’in gördüğü red
printf 'import nox.time\nprint(1)\n' > /tmp/bad.nox

# dekoratör tek başına yeter; aynı fonksiyon dekoratörsüz geçer

    return 1
print(now_ms())

```

### Çözüm

Asıl iş `genDecoratorMetadata`’yı LLVM’de üretmek, sonra `codegen.zig` 1831’deki reddi kaldırmak.

QBE tablosu (`decorators.zig`, `RECORD_WORDS = 5`, kayıt 40 bayt):

| Ofset | Alan |
|---:|---|
| 0 | `func_name` pinned `str*` |
| 8 | `dec_name` pinned `str*` |
| 16 | `arg_count` |
| 24 | `arg_start` (`$__nox_decorator_args` indeksi) |
| 32 | `is_handler` 0/1 |

Yan tablolar: `$__nox_decorator_args`, `$__nox_decorator_arg_kinds` (`0` string, `1` int, `2` bool, `3` string listesi), `$__nox_decorator_list_items`. Üstlerine `nox.reflect`in çağırdığı `__nox_reflect_decorator_count`, `_target_name`, `_name`, `_arg_count`, `_arg`, `_arg_kind`, `_arg_int`, `_arg_bool`, `_arg_list_len`, `_arg_list_item`, `_is_handler`, `_handler`.

Stringler `internPinnedStringConst` ile ARC-pinned olmalı; LLVM string yolu zaten var (`llvmStrHeaderConstant`, codegen.zig 1835 civarı). `qbeRaw` / `qbeRawAll`’ı genel bir “ham metin dök” haline getirme. Dekoratör tablosunu açık LLVM global olarak yaz.

`@capability.requires` kayıtlarını `decorated_functions` dışına almak Aether bench’ini açar, çünkü Aether grafiğindeki tek dekoratör budur ve kapı zaten checker’da. Bu, `nox.reflect.decorator_*` ile `@route` dekoratörlerini `--release`’te yine kırık bırakır. Hedef o daraltma değil; metadata’nın LLVM’de üretilmesi.

Kabul:

1. `/tmp/dec.nox` ve `import nox.time` / `nox.crypto` / `nox.uuid` / `nox.log` `--release` ile derlenir ve QBE ile aynı sonucu verir.
2. `nox.reflect.decorator_count` dekoratörlü bir programda QBE ile aynı sayıyı döner.
3. Freestanding profilde `nox.time.now_ms()` hâlâ `CapabilityNotGranted` olur. Tablo üretimi bu kontrolü kaldırmaz.
4. `AETHER_SKIP_RELEASE` olmadan `benchmarks/run.sh` Aether `--release` satırını üretir.
5. `compiler/main.zig` 2046 civarındaki genel mesaj, reddin dekoratör tablosundan geldiğini söyler. Eski “iç içe fonksiyon” örneği bu vaka için kalmasın.

### 1.129’da ikinci duvar

LLVM reddi düzelince Aether’i **noxc 1.129** ile derlemek ayrı bir tip hatasına düşer. 1.127.0 `HttpRequest` kurucusuna `peer_addr: str` ekledi. 1.126 kurucusu 4 alanlı. Aether 0.6.6 hâlâ 4 argüman geçiriyor (`application.nox` `dispatch_from_parts`, satır 537):

```text
tip hatasi (ArgumentCountMismatch): 'nox_http_HttpRequest' 5 argüman bekler, 4 verildi
```

1.126 stdlib’i ile yalnızca LLVM işi yeter. 1.127+ stdlib ile `HttpRequest(..., peer_addr)` ve `peer_addr` okuyan her Aether çağrı sitesi birlikte güncellenir. Bench fairness’i bozmamak için ping/echo `peer_addr` okumamalı.

## 2. Echo neden ping’den uzak

### Sayılar

Dört sunucu aynı anda, 8 saniye. Aether QBE, `AETHER_WORKERS=1`. Gin ve Axum tüm çekirdekler. `--release` satırı yok (madde 1).

| Hedef | GET /ping | POST /echo | echo’nun eklediği süre |
|---|---:|---:|---:|
| Axum | 206 452 (4.84 µs) | 203 188 (4.92 µs) | **0.08 µs** |
| Gin | 193 169 (5.18 µs) | 184 062 (5.43 µs) | **0.26 µs** |
| Aether QBE | 155 267 (6.44 µs) | 116 402 (8.59 µs) | **2.15 µs** |
| NestJS Express | 64 417 (15.5 µs) | 50 442 (19.8 µs) | **4.3 µs** |

Karşılaştırılacak olan oran değil, istek başına ek mikrosaniye. Aether’in JSON katmanı bu oturumda Gin’den yaklaşık sekiz kat, Axum’dan yaklaşık yirmi beş kat pahalı.

İzole 1.104 ölçümü (Nest/Gin kapalı, aynı fairness bayrakları): ping 156 305 (6.40 µs), echo 130 595 (7.66 µs), ek **1.26 µs** (%16). Bu oturumda ping yerinde kaldı, echo 130 595 → 116 402 düştü. Echo CPU’yu daha çok kullandığı için diğer üç sunucuyla aynı makinede daha fazla kaybetti. Yapısal hedef 1.26 µs bandı. 2.15 µs’nin üstü yarış.

`wrk` socket read hataları yalnız Aether’de (ping 1237, echo 921). İki rotada da var; echo/ping farkını açıklamaz. Ayrı iş (PERF_GAPS G4).

### Ping ne yapıyor

`benchmarks/aether/main.nox` `ping_handler` → `json_ok("{\"pong\":true}")`. Decode, şema ve encode yok. Gövde sabit `str`.

### Echo ne ekliyor

`m.post_body("/echo", ...)` → `validation_pipe` (`pipe.nox`):

1. `ctx.body()`
2. `parse_value_or_raise` (`dto.nox`): bir `nox.json.decode`, sonra `nox.validate.validate(schema.flat())`. Echo şeması tek zorunlu `string` alan. `format` / min / max yok, `_schema_needs_extra` false, ikinci Aether turu yok.
3. `from_decoded` (`body.nox`) `JsonValue`’yu `ValidatedBody._jsons` içinde tutar. Handler ikinci kez decode etmez.

Handler:

4. `ctx.input_str("msg")` → `get_str` → `object_len` / `object_key` / `object_value` ile doğrusal tarama, sonra `is_string` + `as_string`.
5. `json_ok_str` → `encode_str_map` tek alan kolu (`response.nox`): `"{" + encode_string(key) + ":" + encode_string(value) + "}"`. Beş parça, dört birleştirme. Çok alan kolu `nox.strings.join` kullanır; tek alan kolu kullanmaz.

Axum `Json<{msg}>` + serde, Gin `ShouldBindJSON` + `c.JSON`: bir deserialize, bir buffer’a serialize. Aether genel `JsonValue` ağacı, şema yorumlayıcısı ve parçalı string kurar.

0.6.3’te kapananlar (tekrar açma): ikinci decode, doğrulama sonrası paralel dizi yürüyüşü, her istekte ikinci format/min/max turu. Kalan 1.26 µs bunlardan sonra ölçüldü. Bu oturum o parçaların iç dağılımını profillemedi. Encode’u körlemesine değiştirmek 1.26 µs’nin küçük bir dilimini oynatır; `encode_str_map` tek alan zaten kısa yol.

`nox.json.JsonWriter` (Nox 1.128.0) yine `list[str]` + join. Tek alanlı echo için `encode_str_map`’in yerine geçmek, düğüm başına ARC’lı decode’u kaldırmaz. Floor 1.104.0 iken writer’a geçmek ayrıca floor yükseltmesidir.

### Çözüm sırası

Önce madde 1, sonra izole A/B. Dört sunucuyu birlikte çalıştırarak karar verme.

Aynı bayraklar, sunucular tek tek, `wrk -t4 -c40 -d8s`:

`AETHER_ENV=production AETHER_WORKERS=1 NOX_POOL_WORKERS=1 AETHER_OPENAPI=0 AETHER_CORS_ORIGINS= AETHER_METRICS=0 AETHER_METRICS_ROUTES=0 AETHER_REQUEST_ID=0 AETHER_REQUEST_HEADERS=0 AETHER_LOG_REQUESTS=0`

Geçici handler’lar (bench hedefine özel, kalıcı API değil):

| Kol | İş | Ne ayırır |
|---|---|---|
| P | mevcut `/ping` | taban |
| B | POST gövdesini aynen 200 döndür | soketten body okuma |
| D | `nox.json.decode` + 200 sabit gövde | decode |
| V | decode + `validate` + 200 sabit gövde | şema |
| E | mevcut `/echo` | tarama + `encode_string` + birleştirme |

Her kolonun ping’e göre ek mikrosaniyesi, hangi Nox/Aether fonksiyonunun iş olduğunu söyler. Ondan önce `encode_str_map` veya `get_str` için kalıcı yama yazma.

Beklenen yön (kanıt A/B’den sonra):

- Büyük dilim D ise iş `nox.json.decode` (düğüm başına `JsonValue` + ARC). Aether ikinci bir decoder yazmaz. Nox tarafında, 1.29.8 arena’sından sonra kalan tahsis.
- Dilim V ise `nox.validate.validate` tek alanlı düz şemada hâlâ genel yorumlayıcı. Echo sözleşmesi (handler’dan önce 400) durur; ucuzlayan şey yorumlayıcının kendisidir.
- Dilim E küçükse `encode_str_map` tek alan birleştirmesi ve doğrusal `get_str` bırakılır.

Kabul: izole QBE echo ek süresi 1.26 µs’nin altına iner ve ping gerilemez. `--release` madde 1 bittikten sonra aynı A/B, `NOX_POOL_WORKERS=1` ile, QBE süreci ayaktayken değil. İki Aether süreci aynı makinede LLVM binary’sini SIGSEGV edebiliyor ([BENCHMARKS.md](BENCHMARKS.md) fairness notu).
